# Demo walkthrough and recording script

Target: under three minutes. Capture actual application behavior only. Do not record secrets, private environment files, real buyer credentials or unrelated user data. Use 1440px desktop recording; keep text readable and avoid spending time typing long briefs. Prepare local users/project beforehand and verify every demonstrated action.

## Preparation

Run the README setup/migration/seed commands. Either use the documented local accounts or create a fresh client/freelancer pair and fresh project for repeatability; seed does not reset existing progress. Use two browser profiles/contexts so client and freelancer sessions stay separate. The demo project budget is $600, with $150/$250/$200 milestones.

For an AI-planning demonstration create a fresh project with no saved milestones. Real mode must be configured and verified before describing it as real AI. Otherwise show the SIMULATED MOCK AI label and state it explicitly. Configure and actually accept a Sandbox checkout before including a successful capture in the recording. Automated checkout fixtures are not valid transaction footage.

## Timeline, narration and clicks

| Time | On-screen action | Narration |
| --- | --- | --- |
| 0:00-0:20 | Landing -> sign in -> dashboard | Freelance milestones break down when completion means different things to each side. VeriFlow makes requirements, evidence and decisions visible. |
| 0:20-0:40 | Create project / open prepared brief | The client records scope, deliverables, a precise budget and an assigned freelancer. Every amount is stored in integer minor units. |
| 0:40-1:05 | Draft AI milestone plan -> review/edit -> save | Planning proposes measurable milestones and allocations. The mode is visible, and suggestions become agreements only after the client reviews and saves them. Say explicitly if this run uses simulated AI. |
| 1:05-1:30 | Freelancer profile -> assigned milestone -> submit evidence | The freelancer supplies a description, reproduction notes and references. Revisions remain in the record. Links are not silently treated as inspected evidence. |
| 1:30-1:55 | Client -> Start review -> request assessment | The advisory report compares every criterion, highlights missing evidence and states limitations. AI cannot approve the work or authorize a payment. |
| 1:55-2:15 | Client decision -> approve current submission with notes | The client independently inspects the deliverables and records the final decision. Only the current submission can be approved. |
| 2:15-2:40 | Load Sandbox checkout -> buyer approval -> receipt | If actually verified: PayPal Sandbox handles buyer approval. The server captures and verifies the identity, status, amount and currency before marking paid. This is test money, not escrow or a freelancer payout. |
| 2:40-2:55 | Payment history -> project audit | Both parties see the same persistent receipt and action history. Retries reconcile the existing order instead of inventing another successful payment. |
| 2:55-3:00 | Dashboard/landing | VeriFlow AI: Verify Work. Build Trust. Pay Smarter. |

## Recovery and truthful alternatives

If AI is unavailable, show the actual error and manual milestone/review workflow; do not quietly substitute mock results. If Sandbox credentials/approval are unavailable, show the disabled/unconfigured message and explain that live acceptance is pending. Do not use a fabricated receipt, edit a database into PAID, or splice controlled test footage into a claimed live transaction. A demo without live Sandbox acceptance does not satisfy the final integration gate.

Save screenshots of dashboard, editable proposal/mode label, evidence/revision, report limitations, human decision, real verified Sandbox receipt (only when available), and audit history. Record with an OS screen recorder, trim to less than three minutes, review for secrets and accuracy, upload to a human-owned public YouTube account, and add the actual link to DEVPOST.md.
